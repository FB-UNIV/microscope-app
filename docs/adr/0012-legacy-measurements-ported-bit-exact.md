# Legacy phase analysis and Vickers hardness are ported bit-exact, not redesigned

**Status:** [ADR 0021](0021-phase-analysis-at-legacy-scale.md) feeds the phase analysis a copy scaled to the legacy 1042 px width when a photo is wider, and reports a missing Seuil instead of the legacy defaults; the algorithm itself is unchanged and still bit-exact on legacy-sized images.

The legacy Metal app's two lab measurements — phase percentage ("Pourcentage des constituants": automatic threshold on an edge-weighted histogram, then dark/light/uncertain pixel counts) and Vickers HV0.5 — were recovered by decompiling `MetalNew-wx3 05-03-2020.exe` and are reimplemented step for step, including integer `(R+G+B)/3` grey, float arithmetic with truncating conversions (the legacy x87 control word chopped), a 5×5 disk opening+closing with its odd border handling, and the HV coefficient 1.85409 (ISO says 1.8544). Considered replacing them with textbook equivalents (Otsu threshold, luminance grey, ISO coefficient) — simpler and arguably "better" — but teachers compare student results against years of archived numbers and expected ranges per steel grade; a modern algorithm that gives a different pearlite fraction on the same photo is a regression to them, not an improvement.

**Consequences:** The code in `src/phase_analysis.cpp` and `src/vickers.cpp` looks over-specific on purpose; each constant is tied to a decompiled address in the comments. `-ffp-contract=off` (`/fp:precise` on MSVC) is required so FMA doesn't change rounding. Parity is guarded by `tests/test_phase_analysis.cpp`, which compares against `tools/legacy_phase_reference.py` (an independent numpy implementation of the same spec) on the legacy CTTM TIFFs — that is spec-vs-spec agreement, not legacy-exe output, since the old exe needs Matrox MIL to run. A modern alternative can be added later as a separate, opt-in method without touching the legacy one.
