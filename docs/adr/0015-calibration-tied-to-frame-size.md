# Calibration is tied to the frame size it was measured at: refuse a mismatch, never rescale

**Status:** the legacy-import path mentioned below was removed by [ADR 0018](0018-no-legacy-migration.md); a Vue now gets a Calibration only by being captured with one. [ADR 0020](0020-calibrate-one-objective-derive-the-others.md) derives every objective not measured on the mire from the one that was, so a new camera mode means recalibrating that one objective, not every one; the frame-size check below applies to derived Calibrations as well.

A Calibration (px/µm for one Grossissement) is only true for the frame size it was measured at. The Moticam A5 profile asks for 3840×2160 MJPG (ADR 0013/0014), but a UVC driver that can't grant a mode silently falls back to another one — the A5 opens at 1024×768 by default (`docs/hardware/camera-probe.md`). A Calibration measured at 4K and applied to a 1024×768 frame is off by 2.8–3.75× in length, and Dureté Vickers goes with 1/d², so HV is off by 8–14× — with nothing on screen to say so. So a Calibration now records its reference frame size (`frame_width`/`frame_height`), and wherever one meets an image — capturing or importing a Vue, adding or rendering an Échelle, a Measurement taken on a Vue — a different size is refused with an error naming both sizes; the operator recalibrates at the new size or restores the camera mode. Loading a Vue is the exception, because ADR 0003 wins there: losing part of a sidecar must never cost the photo. A sidecar `"calibration"` or an Échelle that doesn't match its own image is dropped instead of refused — the photo, its other treatments and its capture info load, and `Vue::sidecarError()` names what was dropped and both sizes. At camera open, `CaptureStation` reports the negotiated frame size and pixel format next to exposure and colour temperature and flags any that differ from the camera profile, so the UI can warn before anyone captures.

Considered rescaling px/µm by the size ratio. Rejected: a size alone can't tell a scaled (binned) mode from a cropped (ROI) one, which need opposite corrections, and the A5's fallback (4:3) isn't even the same aspect ratio as the profile (16:9), so no single factor exists. Considered warning only and letting the measurement through. Rejected: a dismissed warning still ends up as a wrong hardness in a student's report, and teachers compare results with archived ones (ADR 0012).

Each Vue's sidecar now holds the Calibration it was captured or imported with under `"calibration"`, beside `"capture"` and `"treatments"`; until now it lived only inside Échelle parameters, so a Vue without an Échelle — every legacy import — lost it on reload. It is a snapshot fixed at capture, like the White reference in ADR 0014: recalibrating an objective changes only future Vues, never past measurements. `"capture"` now records what the camera actually applied rather than what the profile asked for — `null` for exposure or colour temperature when the camera refused them (or ran on auto) — plus the frame size and pixel format of the stored frame.

**Consequences:** Calibration is per Grossissement *and* frame size: changing the camera mode means recalibrating every objective, and the calibration wizard must record the frame size it measured at. Calibrations without a frame size (Échelle parameters in pre-ADR-0015 sidecars) are accepted unverified rather than refused, so existing Vues keep loading. A Vue whose sidecar Calibration was dropped at load measures as uncalibrated (a Measurement on it is refused) until it is recaptured, and one whose Échelle was dropped renders without the bar. The dropped values are not erased: the next save moves the old sidecar aside to `<sidecar>.mismatched` before writing (ADR 0004), the same way an unreadable sidecar is kept as `.unreadable`. `Treatment` gains `frameMismatch()` so `Vue` can check a treatment against its frame without rendering it. Bare-array sidecars (pre-ADR 0014) and object sidecars without `"calibration"` load as uncalibrated Vues. `ICamera` gains `frameSize()` and `pixelFormat()` (empty = backend can't tell); `CaptureStation` treats "can't tell" as not granted when the profile requested a mode.
