# Colour: lock the camera's colour temperature and bake a per-microscope White reference into every capture

Two probe runs on the Moticam A5 (`docs/hardware/camera-probe.md`) showed its automatic white balance is unstable — the same plain wall came out pink in one run and lavender in the next — and every frame was short on green. UVC exposes white balance only as a colour temperature, which moves colours along the blue↔yellow axis and cannot remove a green/magenta tint. The legacy app solved the same problem with per-workstation R/G/B gains (R 1.745, G 1, B 2.576 in its last config). So colour is fixed in two layers: the camera profile locks a colour temperature (stops frame-to-frame drift), and a **White reference** — R/G/B gains measured once per microscope from a blank field — is applied in software by `CaptureStation` and baked into the saved original. The profile (exposure and colour temperature) is re-applied on every camera open because the A5 keeps whatever the previous program set.

Considered applying the gains as a Treatment, which would leave the camera's bytes untouched in the spirit of ADR 0003. Rejected: the "as captured" original is already shaped by station settings (exposure, colour temperature, MJPG compression), and the White reference is one more station setting; phase analysis should always see corrected colour without depending on every Vue carrying an extra Treatment.

**Consequences:** Each Vue's sidecar now records how it was captured under `"capture"` (backend, exposure, colour temperature, the gains baked in), and the sidecar becomes an object `{"capture", "treatments"}`; bare-array sidecars from before still load. Recalibrating a microscope changes only future captures — past Vues keep their recorded gains. A wrong White reference is baked in like a wrong exposure would be: recalibrate and recapture. Each microscope needs a calibration step in the setup UI (blank field, lamp on); until then gains stay identity and the locked colour temperature alone applies.
